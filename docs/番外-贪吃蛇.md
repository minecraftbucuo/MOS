# 番外篇：贪吃蛇——把前面所有章节串成一个游戏

## 这一章要做成什么

第八章结束时我们有了：屏幕（05/06 章）、中断和键盘（07 章）、页帧分配器和内核堆（08 章）。它们各自都验证过了，但还像一堆零件散在桌上。这一章把它们装成一整台机器：**一个能玩的双缓冲贪吃蛇**，跑在内核里。

要写的文件只有一个：`kernel/src/game.rs`（约 350 行）。它不发明新的底层机制，所有底层能力都是前面章节现成的：

| 谁服务它 | 给它什么 | 来自哪章 |
|---|---|---|
| `console` | 帧缓冲地址、行距、整屏尺寸，`blit()` 上屏 | 05/06 章 |
| `font` | ASCII 字模表（分数、GAME OVER 文字用） | 06 章 |
| `interrupts` | 滴答数 `ticks()`——游戏的节拍和随机种子 | 07 章 |
| `keyboard` | 按键队列 `pop_key()`——方向键和重开 | 07 章 |
| `heap`（GlobalAlloc） | 整块屏外画布（真机 2.5K 屏上是 16MB） | 08 章 |

先讲两个决定整个写法的原理，再逐段读代码，最后一次性运行验证。

## 原理一：游戏循环——中断记账，主循环干活

贪吃蛇的本质需求是两件互不相关的事按各自的节奏发生：

- **蛇每 100 毫秒走一步**（时间驱动）
- **玩家随时按方向键**（事件驱动）

最直觉的写法是"键盘中断里直接改蛇的方向，时钟中断里直接走一步"——但那是错的，本项目自始至终坚持：

> **中断处理函数只记账，不做业务。**

理由有三：中断处理里不知道会被谁打断，跑游戏逻辑等于把长代码暴露在并发风险里；中断要短，慢了会丢键、丢拍；而且真机会翻脸（见本篇末尾的踩坑和《真机时钟悬案》——时钟中断在真机上压根不来，如果游戏逻辑长在中断里，游戏就跟着死了）。

所以分工是：

```
时钟中断（IRQ0） → 只做 TICKS += 1
键盘中断（IRQ1） → 只把扫描码翻译进队列
主循环           → 滴答变了就调 on_tick()：
                    取光按键队列 → 到步点走一步 → 重画 → 上屏
```

这是所有游戏循环乃至操作系统调度器的通形：**生产者（中断）只投递事实，消费者（主循环）按自己的节奏消化**。09 章的调度器就是把 `on_tick` 里的"走一步棋"换成"挑一个进程跑一段"。

## 原理二：双缓冲——为什么不能直接画显存

显示硬件每隔十几毫秒把显存整个刷上屏幕。如果直接往显存里画，刷新很可能逮到"画到一半"的瞬间：擦掉的旧格子还没擦干净、新的蛇头还没画上——肉眼看到的就是蛇身一闪一闪、拖着残影。

解法是**双缓冲**：画面先画进一块屏外内存（**后备缓冲**，back buffer，就是堆上分配的那块画布），这一整帧画完，再一口气 `memcpy` 到显存。拷贝是线性的、顺序的，就算中途被刷新逮到，看到的也只是"上半帧是新的、下半帧是旧的"——一帧之差，人眼无感。

内存账本：QEMU 1280×800 的画布是 1280×800×4 ≈ 4MB；真机 2560×1600 是 **16MB**——这就是 08-4 章把堆做大、08-5 章让堆跟着屏幕尺寸走的原因。没有第八章，这个游戏开不了局。

## 逐段读代码

### 常量：格子、颜色、步频

```rust
/// 棋盘格子的边长（像素）。正方形，蛇和食物都占一格
const CELL: usize = 16;

/// 颜色。显存像素排布 0x00RRGGBB——红在最高字节
///（第 05 章渐变图 (r << 16) 验证过；console.rs 的旧注释写反过，已纠正）
const FOOD_COLOR: u32 = 0x00CC0000; // 红：食物，也是 GAME OVER 的标题色
const SNAKE_COLOR: u32 = 0x0000CC00; // 绿
const BG_COLOR: u32 = 0x00000000; // 黑
const TEXT_COLOR: u32 = 0x00FFFFFF; // 白
const DIM_COLOR: u32 = 0x00888888; // 灰：提示文字

/// 步频分频：时钟 100Hz，每 10 滴答走一步 = 每秒 10 步
const STEP_INTERVAL: u64 = 10;
```

棋盘不是新东西，就是屏幕本身：宽 `屏宽/CELL` 列、高 `屏高/CELL` 行。QEMU 里 80×50 格，真机 2.5K 屏 160×100 格——同一份代码，棋盘大小跟着屏幕走。

`STEP_INTERVAL` 把"滴答"换算成"步"：时钟 100Hz，攒满 10 个滴答走一步。想调游戏难度改这一个数就行。

### 游戏状态：一个结构体说清全部

```rust
/// 游戏进行到哪个阶段了
enum Phase {
    Play,
    Over,
}

/// 游戏状态。棋盘 = 屏幕按 CELL 切成的正方形网格
struct Game {
    cols: usize,
    rows: usize,
    /// 蛇身：格子坐标列表，**末尾是蛇头**（push 进头、remove 出尾）
    body: Vec<(usize, usize)>,
    dir: (i32, i32),      // 前进方向 (列增量, 行增量)
    food: (usize, usize), // 食物所在格子
    rng: u64,             // 伪随机数状态（种子 = 开机滴答数）
    phase: Phase,
    score: usize,
    buf: *mut u8,   // 后备缓冲：屏外画布（堆上的一整块）
    pitch: usize,   // 画布行距（字节），与显存一致
    size: usize,    // 画布总字节数（整屏涂黑用）
}
```

两个值得停一秒的决定：

- **`body` 的末尾是蛇头**。走一步 = `push` 新头 + `remove(0)` 旧尾，方向变更只看头两节——蛇的全部行为就用这两个操作表达，不需要链表。
- **方向用 `(列增量, 行增量)` 存**，右 = `(1, 0)`、上 = `(0, -1)`。走一步就是头坐标加上它，判墙、判身都发生在加出来之后。

`buf` 是裸指针不是 `Vec`：画布就是一大块像素内存，要的是"从这开始、这么大"，Vec 的自动回收反而是累赘（见踩坑实录第二条）。`pitch`（行距）从 console 拿：显存一行实际占的字节数可能大于 `宽×4`（行尾有硬件填充），画布必须与之一致，`blit` 才能逐行对上。

### 随机数：LCG，裸机唯一的现成选择

```rust
/// 线性同余生成器（LCG）：一次乘法一次加法，输出"看着像随机"的数。
/// 裸机没有现成随机源，拿开机以来的滴答数当种子——每次开机都不同
fn next_rand(&mut self) -> u64 {
    self.rng = self
        .rng
        .wrapping_mul(6364136223846793005)
        .wrapping_add(1442695040888963407);
    self.rng
}
```

放食物要随机。没有操作系统、没有 `/dev/urandom`，最便宜的伪随机就是 LCG：新状态 = 旧状态×A+B（A、B 是文献里挑好的常数，`wrapping` 表示按无符号数回绕算，不 panic）。种子用 `interrupts::ticks()`——你开机到点开食物之间经过了多少滴答基本是随机的，于是每次开局的蛇和食物都不同。

安全性？它不安全，可预测。但贪吃蛇的食物只需要"看着乱"，不需要密码学强度。

### 渲染原语：paint、px、text

```rust
/// 把一个格子画进后备缓冲
fn paint(&self, col: usize, row: usize, color: u32) {
    for yy in 0..CELL {
        // 一行的起点 = 基址 + 像素行 × 行距 + 格子左边缘
        let row_base = (row * CELL + yy) * self.pitch + col * CELL * 4;
        for xx in 0..CELL {
            unsafe {
                let p = self.buf.add(row_base + xx * 4) as *mut u32;
                p.write_volatile(color);
            }
        }
    }
}
```

这是全模块唯一"碰内存"的像素函数，其余都从它（或它的单像素版 `px`）组合出来。地址公式的层次：`格子 → 16 行像素 → 每行 16 个像素 → 每像素 4 字节`，乘上 `pitch` 而不是 `宽×4` 是对行尾填充的尊重。

`write_volatile`：这块内存没有别的别名，其实不必 volatile——但 06 章写显存时用过它，这里沿用同一种谨慎，也提醒读者"这是 MMIO 风格的裸内存"。

```rust
/// 把一行 ASCII 文字画进后备缓冲（逐字取字模，亮点描 fg、暗点描 bg）。
/// col_px/row_px 是像素坐标。font.rs 的字模表本来就是公开的，直接取用
fn text(&self, col_px: usize, row_px: usize, s: &[u8], fg: u32, bg: u32) {
    for (i, &b) in s.iter().enumerate() {
        let glyph = &GLYPHS[b as usize];
        let x0 = col_px + i * GLYPH_WIDTH;
        for (dy, &bits) in glyph.iter().enumerate() {
            for dx in 0..GLYPH_WIDTH {
                let c = if bits & (0x80 >> dx) != 0 { fg } else { bg };
                self.px(x0 + dx, row_px + dy, c);
            }
        }
    }
}
```

逐字取字模、逐位判亮暗、亮描前景色暗描背景色——和 06 章控制台一个原理，只是画进了画布而不是直接上显存。`bg` 故意可指定：HUD 文字背后垫黑色，蛇从分数底下钻过时文字永远压在上面，画面不会花。

### 放食物：随机 + 避开蛇身

```rust
/// 把食物放到随机格子（避开蛇身占着的格子），画进缓冲
fn place_food(&mut self) {
    loop {
        let r = self.next_rand();
        let p = ((r as usize) % self.cols, ((r >> 32) as usize) % self.rows);
        if !self.body.contains(&p) {
            self.food = p;
            self.paint(p.0, p.1, FOOD_COLOR);
            return;
        }
    }
}
```

一次 LCG 输出拆两半用：低 32 位选列、高 32 位选行。撞上蛇身就再掷一次——蛇最长也就占棋盘一小半，循环很快能落地。

### 走一步：整个游戏的"业务核心"，其实只有 30 行

```rust
/// 蛇走一步：判死、擦尾、长头、吃食物，最后翻页上屏
fn tick(&mut self) {
    let (hx, hy) = *self.body.last().unwrap(); // 蛇头现在在哪
    // 撞墙判死：头走出棋盘就是终点（不再穿墙）
    let nx = hx as i32 + self.dir.0;
    let ny = hy as i32 + self.dir.1;
    if nx < 0 || ny < 0 || nx >= self.cols as i32 || ny >= self.rows as i32 {
        self.game_over();
        return;
    }
    let (nx, ny) = (nx as usize, ny as usize);

    let ate = (nx, ny) == self.food;
    if !ate {
        // 尾巴先出列，那格画回背景色——
        // 漏了这步就是"蛇走一路掉一节"，蛇身会越拖越长
        let tail = self.body.remove(0);
        self.paint(tail.0, tail.1, BG_COLOR);
    }
    // 咬到自己判死（判断的是出列尾巴之后的蛇身）
    if self.body.contains(&(nx, ny)) {
        self.game_over();
        return;
    }

    self.body.push((nx, ny));
    self.paint(nx, ny, SNAKE_COLOR);
    if ate {
        self.score += 1;
        self.place_food();
    }
    self.paint_score();
    console::blit(self.buf);
}
```

顺序全是讲究：**先判墙**（出界直接终局）；**没吃到才收尾**（吃到时尾不动，蛇才变长）；判咬自己要放在收尾**之后**——蛇追上自己尾巴尖的那一格，本该是"尾巴刚挪走让出来的空格"，提前判就误杀了；最后 `blit` 一次翻页，这一步的全部渲染（擦尾、画头、重画 HUD）都在屏外完成。

### 终局与重开：不重新分配

```rust
/// 原地重开：重置状态、重画第一帧。注意不能重新 init——
/// bump 堆不回收，每死一次就分配一块新画布的话，两局堆就见底了
fn reset(&mut self) {
    self.body.clear();
    // ……重置状态、清屏、画蛇和食物、blit……
}
```

注释里那句是 08-4 章 bump 堆的回响：它只进不出，`free` 是空操作。所以画布**只在开局分配一次**，重开是原地复用——状态清零、画布涂黑、重画第一帧。

### on_tick：主循环的对接点

```rust
/// 主循环每个滴答调一次。先消化按键队列（中断攒下的事件），
/// 再按阶段处理：Play 里到步点走棋；Over 里等空格重开
pub fn on_tick(t: u64) {
    // 方向键走扩展码（0xE0 前缀），WASD 走普通字符码——两条路都通
    let mut restart = false;
    while let Some(k) = keyboard::pop_key() {
        match k {
            keyboard::KEY_UP => set_dir(0, -1),
            keyboard::KEY_DOWN => set_dir(0, 1),
            keyboard::KEY_LEFT => set_dir(-1, 0),
            keyboard::KEY_RIGHT => set_dir(1, 0),
            b'w' => set_dir(0, -1),
            b's' => set_dir(0, 1),
            b'a' => set_dir(-1, 0),
            b'd' => set_dir(1, 0),
            b' ' => restart = true,
            // 诊断键（真机时钟案，自愿使用）：H 探测 HPET，C 清位尝试
            b'h' => acpi::probe(),
            b'c' => acpi::try_clear(),
            _ => {}
        }
    }
    // ……到步点走棋 / 空格重开……
}
```

`while let Some(k) = pop_key()` 一次取光积压的按键（中断可能在两次 on_tick 之间攒了不止一个）。`set_dir` 里有一道防 180 度调头的闸——而且光查"是否与当前方向相反"不够：一步之内连按两键（比如先按 w 再按 a）能拼出反向绕过检查，所以它实际验证的是"新方向走一步不许落在蛇脖子的格子上"。

H 和 C 两个键是真机时钟悬案的诊断工具，与本游戏无关，不按即不存在。

### init：画布从堆里来

```rust
pub fn init() {
    let (w, h) = console::pixel_size();
    let (pitch, size) = console::canvas();
    if w == 0 || h == 0 || size == 0 {
        // 没有屏幕（个别真机固件给 Limine 的 framebuffer 请求吃闭门羹）。
        // ……不开局，让屏幕保持引导器留下的样子，别无声无息地挂死
        return;
    }
    let (cols, rows) = (w / CELL, h / CELL);

    // 后备缓冲：整块屏外画布，从堆里要（堆已按屏幕尺寸扩好）
    let buf = unsafe { alloc(Layout::from_size_align(size, 4096).unwrap()) };
    if buf.is_null() {
        // 画布跟屏幕一样大，屏幕越大要得越多——真机 2.5K 屏的画布 16MB，
        // 堆开小了这一步就失败。上屏报错，绝不无声无息地不开局
        //（这次的教训：静默失败最难查，屏幕停在启动文字上像冻住一样）
        console::print("game: canvas alloc FAILED!\n");
        return;
    }
    // ……建 Game、reset 摆第一帧……
}
```

两道防御各对应一次真机血案（详见踩坑实录）：屏幕尺寸为 0 时不开局，是怕 `place_food` 里 `% self.cols` 除以零；画布分配失败要**喊出来**，是上一版静默 `return` 让"堆不够"伪装成了"死机"。

## 运行验证

代码全部讲完了，现在跑：

```
make run
```

预期看到：

1. 启动文字滚过后出现黑色游戏画面：左上角 `SCORE 0` 和灰色诊断行，屏幕中间一条向右爬的四节绿蛇，一颗红色食物
2. **不碰键盘**，蛇以每秒 10 格的速度自己爬；串口每秒打印一行 `[timer] Ns`
3. 方向键 / WASD 转向，吃食物变长、分数 +1
4. 撞墙或咬到自己 → 居中红色 `GAME OVER` + 分数 + `SPACE TO RESTART`
5. 空格重开，画面恢复第 1 步的样子

常见失败：

| 现象 | 原因 |
|---|---|
| `game: canvas alloc FAILED!` | 堆没跟上屏幕尺寸——检查 main.rs 里堆页数是否按 `console::canvas()` 算的 |
| 蛇不动、按一下动一下 | 时钟中断没来。QEMU 里不该发生；真机上见《番外-真机时钟悬案》 |
| 画面闪烁有残影 | 渲染没走画布、直接画了显存 |
| 蛇越走越长 | `tick` 里漏了收尾擦尾那两行 |

## 踩坑实录

**坑 1：真机画布 16MB，QEMU 里 4MB，堆按 QEMU 配。** QEMU 一切正常，真机开局静默失败——因为堆只有 4MB 出头，装不下 2.5K 屏的画布。更糟的是失败路径是无声 `return`，屏幕停在启动文字上，看上去像死机。修法：堆大小跟着屏幕尺寸走 + 失败必须上屏喊出来。**静默失败比崩溃难查十倍，因为它的现场是干净的。**

**坑 2：重开不能重新分配。** 一开始 `reset` 里图省事重新走了一遍分配逻辑——bump 堆不回收，两局就见底。画布类大资产：分配一次，终身复用。

**坑 3：真机上蛇"按一下键才动一下"。** 这不是本章的坑，是下一章整个悬案的开端——真机的时钟中断一次都没来过，主循环的 `hlt` 只有键盘能叫醒。完整推理和修复（轮询 PIT 备用心跳）在《番外-真机时钟悬案》。

## 小结与下一章预告

这一章没有新的底层机制，却把 05~08 章的全部产出捏成了一个活物：帧缓冲是它的纸，字模表是它的笔，中断是它的节拍器和键盘，内核堆供起了它 16MB 的画布。更重要的是 `中断记账、主循环干活` 这个结构——把 `on_tick` 里"走一步棋"换成"挑一个进程跑一段"，它就是 09 章的调度器。
