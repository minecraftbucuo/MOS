# 03 · 串口输出：让内核开口说话

> 上一章：[02-第一个内核](02-第一个内核.md)。内核已经能编译，但它是个"哑巴"——
> 死循环里发生了什么，外界一无所知。这一章给内核装上第一件"器官"。
>
> 本章结构：**为什么 → 是什么 → 怎么做**。读完这章再动手，写代码只是
> 把理解翻译成 Rust 的过程。

## 1. 为什么：没有输出，等于盲飞

三个理由决定了"串口输出"必须是内核的第一个功能：

1. **调试是开发 OS 的主要工作**。改一行代码 → 跑 → 黑屏/卡死 → 你知道什么？
> 什么都不知道。没有日志的内核开发，就像不看仪表盘开飞机。
2. **串口是整机里最简单的外设**。初始化只要往几个寄存器写字节，总共
   30 行左右代码——而屏幕输出（帧缓冲）需要自己画像素、画字体，工作量
   大十倍。先用最短路径让内核"能说话"，再考虑"说得好看"。
3. **串口贯通开发和真机两个世界**。QEMU 一条参数就能把串口接到你的
   终端（`-serial stdio`）；真机出问题时，串口日志（配合一根 USB 转
   串口线）是唯一的"黑匣子"。

类比：学单片机时大家先点灯，串口之于内核就是那盏灯——只不过它闪的
是字符。

## 2. 是什么：UART 芯片与端口 IO

### 2.1 UART 是什么

UART（通用异步收发器）是主板上的一块小芯片（具体型号 16550），它管理
"串口"——一根按位发送数据的线。历史上串口用来接调制解调器、鼠标，
如今在 PC 上的主要用途就是**调试输出**。我们用的是第一个串口 **COM1**。

它的使用模型简单到感人：

```
CPU 写一个字节到"数据寄存器" ──► UART 一位一位发出去 ──► 接收端显示字符
```

### 2.2 端口 IO：x86 的第二个地址空间

关键概念：x86 CPU 有**两套地址空间**，这是它和 ARM 等架构的重要区别：

| | 内存地址空间 | IO 端口空间 |
|---|---|---|
| 访问指令 | `mov`（普通读写） | `in` / `out`（专用指令） |
| 常住者 | RAM、显存 | UART、PIT 定时器、PS/2 键盘控制器等老式外设 |
| 容量 | 按位数定（64 位） | 只有 65536 个端口 |

UART 的寄存器就挂在端口空间里，COM1 的基址是 `0x3F8`。所以"往串口
写一个字节"的硬件动作是：**执行 `out` 指令，端口地址 0x3F8，数据是要发的字节**。

> 注意：这是"老式"外设的接法。现代设备（NVMe 硬盘、xHCI USB）大多挂在
> 内存空间（MMIO），用普通 `mov` 访问。两种都会用到，先把简单的拿下。

### 2.3 UART 的寄存器（只认识 4 个就够用）

UART 的寄存器通过"基址 + 偏移"访问，偏移 0~7。常用的就这几个：

| 偏移 | 名字 | 用途 |
|---|---|---|
| +0 | 数据口 | **写**它 = 发送一个字节；读它 = 收到的字节 |
| +1 | 中断使能 | 阶段 0 先全部关掉（0x00） |
| +3 | 线路控制 | 设置数据格式 + 一个开关位 DLAB |
| +5 | 线路状态 (LSR) | bit 5 = **发送器空闲**（1 表示可以再写） |

为什么要有"发送器空闲"位？因为 UART 发送有物理速度（波特率，比如每秒
38400 位），你往数据口写得比它发得快，多出来的字节就**丢了**。所以每次
写之前要看一眼 LSR 的 bit 5——像往一个正在漏水的杯子里倒水，先看水位。

### 2.4 波特率与初始化

"波特率"= 每秒传输的位数。QEMU 的模拟 UART 不太在乎这个值，但真机
上收发双方必须约好同一个速率。初始化时通过"除数"寄存器设定（基址
38400 时除数 = 3）。DLAB 开关位的作用：除数寄存器和数据口共用偏移 0/1，
拨 DLAB=1 时偏移 0/1 变成除数寄存器，设完再拨回 0——一分钱掰两半用的
历史设计，认识了就不觉得怪。

### 2.5 为什么绕不开 unsafe

访问端口要用 `in`/`out` 指令，Rust 没有内建语法，只能内联汇编。
而这必然是 `unsafe`：**编译器看不见 UART 的存在**，它无法验证 0x3F8
是个有效端口、写它是否安全。这正是 unsafe 存在的意义——不是"危险代码
垃圾场"，而是"编译器无法担保、由程序员签字画押"的边界。内核里几乎
每一行硬件操作都住在这里，我们会把 unsafe 圈得尽可能小。

## 3. 怎么做：三步走

### 第 1 步：端口读写原语（serial.rs 的地基）

```rust
use core::arch::asm;

/// 往 IO 端口写一个字节
/// out 指令的固定用法：数据放 al，端口地址放 dx
pub unsafe fn outb(port: u16, value: u8) {
    unsafe {
        asm!("out dx, al", in("dx") port, in("al") value,
             options(nomem, nostack, preserves_flags));
    }
}

/// 从 IO 端口读一个字节（下一章收键盘数据时会用到）
pub unsafe fn inb(port: u16) -> u8 {
    let value: u8;
    unsafe {
        asm!("in al, dx", out("al") value, in("dx") port,
             options(nomem, nostack, preserves_flags));
    }
    value
}
```

`options(nomem, nostack, ...)` 是告诉编译器这段汇编不碰内存不碰栈、
不改标志位——让它能放心优化周围代码。这是 Rust 内联汇编的"说明书写法"。

### 第 2 步：SerialPort 结构与初始化、发送

```rust
pub struct SerialPort { base: u16 }   // base = 0x3F8 (COM1)

impl SerialPort {
    /// 初始化：关中断 → 设波特率 → 定格式(8N1) → 开 FIFO
    pub fn init(&mut self) {
        unsafe {
            outb(self.base + 1, 0x00);   // 关串口中断
            outb(self.base + 3, 0x80);   // DLAB=1，接下来访问除数
            outb(self.base + 0, 0x03);   // 除数低字节=3 → 38400 波特
            outb(self.base + 1, 0x00);   // 除数高字节
            outb(self.base + 3, 0x03);   // DLAB=0；8 数据位、无校验、1 停止位
            outb(self.base + 2, 0xC7);   // 开 FIFO，清空，14 字节阈值
            outb(self.base + 4, 0x0B);   // 数据终端就绪+请求发送
        }
    }

    /// 发送一个字节（带忙等待）
    fn send_raw(&mut self, data: u8) {
        unsafe {
            // 等 UART 消化完上一个字节（看 2.3 节的"漏水杯子"）
            while inb(self.base + 5) & 0x20 == 0 {}
            outb(self.base, data);
        }
    }

    /// 发送字符串，'\n' 自动补 '\r'
    pub fn send_str(&mut self, s: &str) {
        for &b in s.as_bytes() {
            match b {
                b'\n' => { self.send_raw(b'\r'); self.send_raw(b'\n'); }
                _ => self.send_raw(b),
            }
        }
    }
}
```

为什么 `\n` 要补成 `\r\n`？这是电传打字机时代的遗产：`\r`（回车）=
打印头回到行首，`\n`（换行）= 纸往上卷一行。串口终端很多还遵循这个
约定，只发 `\n` 的话有些终端会显示成"楼梯"。

### 第 3 步：全局单例 + kmain 里说话

串口全局只有一份，用一个 `static` 加自旋锁（`spin` crate）包起来，
然后在 `kmain` 里：

```rust
serial().send_str("\n=== MOS booting ===\n");
serial().send_str("hello from kernel!\n");
```

到这一步代码就完成了。**但要看到输出，还差最后一块拼图**：内核现在
没人加载（Limine 还没登场）。所以下一章我们把引导器接上、打出 ISO、
在 QEMU 里按下"开机键"——那将是整个项目第一次"开机"的时刻。

## 4. 本章小结

- **为什么**：没日志=盲飞；串口是最短路径的输出通道
- **是什么**：UART 芯片；x86 双地址空间（内存 vs IO 端口）；`in`/`out`
  指令；LSR 忙等待；unsafe 的真正含义（编译器无法担保的边界）
- **怎么做**：`outb/inb` 原语 → `SerialPort`（init + send）→ 全局单例

> 动手时你会写的新知识：`asm!` 内联汇编的寄存器绑定、`spin::Mutex`
> 保护内核数据结构——这是内核里最常用的同步原语。
