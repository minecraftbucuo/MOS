# 03 · 串口输出：让内核开口说话

> 上一章：[02-第一个内核](02-第一个内核.md)。内核已经编译出来了，
> 但它是个哑巴——死循环里发生了什么，外界一无所知。
> 这一章给它装上第一件"器官"。

想象你把一个朋友关进了隔音房，想知道他在里面干什么，唯一的办法是装一个对讲机。内核现在就住在隔音房里，这一章我们装的就是对讲机：**串口**。

而且等不了了。从这一章起，每次跑内核都可能黑屏、卡死、静悄悄地死掉——没有输出通道，出了问题你连"死在哪一步"都不知道。就像不看仪表盘开飞机，盲飞。所以输出必须是内核的第一个功能，一刻都不能往后排。

## 跟谁说：挑一条最简单的嗓子

没有 `println!`（它是标准库的，标准库依赖操作系统，而我们正在写操作系统），想要输出就只能直接跟硬件打交道。

跟哪块硬件说？候选名单上第一个是屏幕。但屏幕是个大工程：要理解像素和颜色，要自己一笔一笔画字体——那是好几章之后的仗。老工程师的传统是先挑软柿子捏：整机里最简单的外设叫**串口**，三十来行代码就能让它出声。

串口是什么？想象一位特别老实的老式电报员：你递给他一张字条，他就一位一位地拍发出去，对面收到的还是那张字条的内容。主板上管这件事的小芯片叫 UART（具体型号 16550），管着第一个串口 **COM1**——就是电脑背后那个梯形的、9 个针的老接口。它年纪比大部分读者都大，如今在 PC 上就剩一个主业：**给内核当调试嘴**。

选它还有一个决定性理由：**它在两个世界都好使**。QEMU 里一条参数（`-serial stdio`）就能把串口接到你的终端；将来真机黑屏时，一根 USB 转串口线就能把内核的遗言引出来。一次投入，开发真机两头受益。

## 怎么递字条：两套门牌的故事

现在问题变成：CPU 怎么把字条递给电报员？

x86 机器里有个乍听很怪的设计：**CPU 有两套地址空间**。你可以把整台电脑想象成一个大商场：

- **内存地址空间**像"店铺地址"——用普通 `mov` 指令就能读写，RAM 和显存住在这里；
- **IO 端口空间**像"服务窗口编号"——必须用专门的 `in`/`out` 指令，UART、定时器、老式键盘控制器这些"老员工"在窗口后面办公。

| | 内存地址空间 | IO 端口空间 |
|---|---|---|
| 访问指令 | `mov`（普通读写） | `in` / `out`（专用指令） |
| 常住者 | RAM、显存 | UART、PIT 定时器、PS/2 键盘控制器等老式外设 |
| 容量 | 按位数定（64 位） | 只有 65536 个端口 |

去窗口办事，你得报窗口号。UART 的窗口号是 **0x3F8**。所以"往串口写一个字节"翻译成硬件动作就是：执行 `out` 指令，端口 0x3F8，带上要发的字节。

> 这套"窗口办公"是老式外设的接法。现代设备（NVMe 硬盘、USB 控制器）大多直接住在"店铺区"（内存空间），用普通 `mov` 访问，那叫 MMIO。两种我们都会用到，先拿下简单的。

## 电报员面板上的按钮

UART 不只有一个窗口，而是一排——窗口号从 0x3F8 起往后数 8 个，各自管不同的事。它就像老设备面板上的一排旋钮，常用的一共 4 个：

| 偏移 | 名字 | 用途 |
|---|---|---|
| +0 | 数据口 | **写**它 = 递一张字条；读它 = 收对方发来的字条 |
| +1 | 中断使能 | 上一章我们谁都不认识，先全部关掉（0x00） |
| +3 | 线路控制 | 定数据格式；还藏着一个开关位 DLAB（见下） |
| +5 | 线路状态 (LSR) | bit 5 = "空闲灯"：亮着（=1）才表示可以递下一张字条 |

为什么要看"空闲灯"？因为电报员拍发电报是有物理速度的（每秒几千位），你递字条递得比他拍得快，多出来的纸条就掉地上了——**丢了**。所以每次递之前先瞄一眼灯：像往一个正在漏水的杯子里续水，先看水位。

面板上还有个古怪设计值得一提：DLAB 开关。UART 的面板按钮不够用，工程师就把 0 号和 1 号按钮做成了"双面按钮"——平时是数据口和中断使能，把 DLAB 拨到 1，它们就翻面变成"波特率除数"寄存器，设完速率再拨回 0。一分钱掰两半用，是那个年代省成本的历史遗产。认识了就不觉得怪。

顺带把"波特率"也说了：它就是双方约好的拍发速度。约定不一致会怎样？你说得快他听得慢，收到的全是乱码——就像两个人没约好语速，一个机关枪一个慢半拍。QEMU 的模拟电报员不太计较这个，但真机两头必须约好（我们用 38400，对应除数 3）。

## 动手之前，先过安检这一关

窗口号、空闲灯、DLAB 开关——上一节的每个动作，接下来都要翻译成 Rust 代码。可是真要动笔，会先撞上一个意想不到的拦路者：**Rust 编译器自己**。

为什么编译器要拦我们？想象它是一位非常负责的安检员：每件行李都要亲眼看过才放行。可是 `out` 指令要递给"0x3F8 窗口"的东西，安检员根本看不见那个窗口——它无法证明 0x3F8 那儿真有个 UART，更无法证明往里写字节是安全的。它的世界名单里没有这扇门。

这时候 Rust 的规则是：你可以过，但要**签字画押**——这个签字栏就叫 `unsafe`。所以 unsafe 不是"危险代码垃圾场"，而是"编译器看不见、由程序员担保"的声明。内核开发里满地都是编译器看不见的硬件，unsafe 会一路相伴；我们的纪律是让每个 unsafe 块**尽量小**，旁边写清楚凭什么安全。

安检的规矩讲明白了，现在真的动笔。

## 动手写：三步递出第一句话

地基——"递字条"和"从窗口取条子"这两个最基础的动作（`out`/`in` 指令的固定用法：数据放 `al`，窗口号放 `dx`）：

```rust
use core::arch::asm;

/// 往 IO 端口写一个字节
pub unsafe fn outb(port: u16, value: u8) {
    unsafe {
        asm!("out dx, al", in("dx") port, in("al") value,
             options(nomem, nostack, preserves_flags));
    }
}

/// 从 IO 端口读一个字节（下一章收键盘数据时会用到）
pub unsafe fn inb(port: u16) -> u8 {
    let value: u8;
    unsafe {
        asm!("in al, dx", out("al") value, in("dx") port,
             options(nomem, nostack, preserves_flags));
    }
    value
}
```

`options(nomem, nostack, ...)` 是递给安检员的说明书：这段汇编不碰内存、不碰栈、不改标志位——你放心优化周围代码。

第二步，把 UART 面板包成一个结构体：开机时把旋钮都拧到正确位置，之后只管递字条：

```rust
pub struct SerialPort { base: u16 }   // base = 0x3F8 (COM1)

impl SerialPort {
    /// 初始化：关中断 → 约速度 → 定格式 → 开 FIFO
    pub fn init(&mut self) {
        unsafe {
            outb(self.base + 1, 0x00);   // 关串口中断（谁都不认识，先静音）
            outb(self.base + 3, 0x80);   // DLAB 拨到 1，接下来访问除数
            outb(self.base + 0, 0x03);   // 除数低字节=3 → 38400 波特
            outb(self.base + 1, 0x00);   // 除数高字节
            outb(self.base + 3, 0x03);   // DLAB 拨回 0；8 数据位、无校验、1 停止位
            outb(self.base + 2, 0xC7);   // 开 FIFO 缓冲，清空，14 字节阈值
            outb(self.base + 4, 0x0B);   // 数据终端就绪 + 请求发送
        }
    }

    /// 递一张字条（递之前看空闲灯）
    fn send_raw(&mut self, data: u8) {
        unsafe {
            while inb(self.base + 5) & 0x20 == 0 {}   // 等空闲灯亮
            outb(self.base, data);
        }
    }

    /// 发送字符串，'\n' 自动补 '\r'
    pub fn send_str(&mut self, s: &str) {
        for &b in s.as_bytes() {
            match b {
                b'\n' => { self.send_raw(b'\r'); self.send_raw(b'\n'); }
                _ => self.send_raw(b),
            }
        }
    }
}
```

为什么 `\n` 要补成 `\r\n`？这是电传打字机时代的化石：`\r`（回车）= 打印头滑回行首，`\n`（换行）= 纸往上卷一行。只发 `\n`，一些串口终端会把字打成"楼梯"——每行比上一行右移一格。

最后一步，串口全机只有一份，用一个 `static` + 自旋锁（`spin` crate）包成全局单例，然后在 `kmain` 里：

```rust
serial().send_str("\n=== MOS booting ===\n");
serial().send_str("hello from kernel!\n");
```

代码到这里就齐了。**但要听到内核说话，还差最后一块拼图**：它现在还躺在硬盘上没人请出场。下一章我们把 Limine 接上、打出 ISO、在 QEMU 里按下"开机键"——那是整个项目第一次真正开机。
