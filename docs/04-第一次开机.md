# 04 · 第一次开机：Limine、ISO 与 QEMU

> 上一章：[03-串口输出](03-串口输出.md)。代码已经会说话了，但还没人听——
> 因为内核依然没人加载。这一章补上最后一块拼图，迎来项目的"开机时刻"。
>
> 本章结构：**为什么 → 是什么 → 怎么做**。

## 1. 为什么：内核自己不会"开机"

回顾 [00-启动流程](00-启动流程.md) 的链条：UEFI 固件只认一种文件——
**EFI 应用程序**。我们的内核是裸机 ELF，UEFI 看都不看它一眼。

所以需要三样东西：

1. **引导器**（Limine）：一个 EFI 应用，UEFI 肯加载它；它再加载我们的
   ELF 内核并跳进去
2. **打包格式**（ISO）：把引导器和内核装进一个"可启动的光盘镜像文件"，
   U 盘和 QEMU 都认这种格式
3. **模拟的 UEFI 固件**（OVMF）：QEMU 默认模拟 90 年代的老 BIOS，
   装上 OVMF 才能模拟 UEFI 环境，和真机行为对齐

三者齐备，"按下电源 → 看到内核日志"这条链路才算通。

## 2. 是什么：三个新面孔

### 2.1 Limine 引导器

[Limine](https://github.com/limine-bootloader/limine) 是社区维护的现代
引导器，我们选它的理由（[00 章](00-启动流程.md)讲过启动链，这里对照）：

- 它替我们干完了所有劝退的脏活：切 64 位长模式、建页表、探测内存、开显示
- **BIOS 和 UEFI 双模式**：同一个 ISO，老机器新机器都能启动——真机
  兼容性直接拉满
- 它给内核的"见面礼"通过**引导协议（boot protocol）**交付：内核用
  请求标记（requests）声明"我要帧缓冲/内存映射"，Limine 按标记准备
  好数据，把指针递给内核

Limine 怎么知道要加载哪个内核？靠配置文件 `limine.conf`——里面写着
启动项的名字、用哪个协议、内核文件在镜像里的路径。

### 2.2 ISO 镜像

ISO9660 是光盘的文件系统格式。我们用 `xorriso` 把一个目录"烧"成
`mos.iso`。这个文件在 QEMU 里当光盘用，`dd` 到 U 盘就是启动盘。
一个目录变三种身份：**目录 → 光盘镜像 → U 盘启动盘**。

### 2.3 OVMF

Open Virtual Machine Firmware，UEFI 固件的开源实现。QEMU 参数里指定
它，模拟器就从"老 BIOS 机器"变身"UEFI 机器"。它分两个文件：
`OVMF_CODE.fd`（固件本体）+ `OVMF_VARS.fd`（可写的设置存储，相当于
真机主板上的 CMOS）。

## 3. 怎么做：从文件到开机

### 3.1 目标产物布局

构建脚本会把各路文件汇进一个临时目录，结构长这样：

```
iso_root/
├── limine.conf          # 启动菜单配置：启动项 + 内核路径
├── mos-kernel           # 我们编译出的内核 ELF（kernel/ 那个成品）
├── limine-bios.sys      # Limine 的 BIOS 模式文件
├── limine-bios-cd.bin   # 同上（光盘引导记录用）
├── limine-uefi-cd.bin   # Limine 的 UEFI 模式文件
└── EFI/BOOT/BOOTX64.EFI # UEFI 固件默认寻找的启动文件（就是 Limine）
```

> `EFI/BOOT/BOOTX64.EFI` 这个路径是 UEFI 规范写死的默认启动路径——
> 固件扫描所有设备，找到这个路径就直接执行它。U 盘之所以"插上就能
> 进启动菜单"，背后就是这条规则。

`limine.conf` 的内容（示意，具体语法以所用 Limine 版本为准，动手时核对）：

```
TIMEOUT=0

:MOS
    PROTOCOL=limine
    KERNEL_PATH=boot:///mos-kernel
```

意思是：启动项叫 "MOS"，用 Limine 协议加载镜像根目录下的 mos-kernel。

### 3.2 构建三步曲（将由 Makefile 自动化）

```
① cargo build                # 编译内核 ELF（第 2 章的流程）
② 汇总 iso_root/ + xorriso 打包成 mos.iso
③ limine bios-install mos.iso   # 往 ISO 里补写 BIOS 模式的引导记录
```

### 3.3 QEMU 开机

```fish
qemu-system-x86_64 \
    -M q35 -m 512M \
    -drive if=pflash,format=raw,readonly=on,file=/usr/share/ovmf/x64/OVMF_CODE.4m.fd \
    -drive if=pflash,format=raw,file=OVMF_VARS.4m.fd \
    -cdrom mos.iso \
    -serial stdio \
    -no-reboot -no-shutdown
```

参数逐个看：

| 参数 | 含义 |
|---|---|
| `-M q35` | 机器型号（较新的芯片组，更接近现代真机） |
| `-m 512M` | 内存 512 MB |
| `-drive if=pflash,...` | 挂载 OVMF 固件（CODE 只读 + VARS 可写） |
| `-cdrom mos.iso` | 插入我们的"光盘" |
| `-serial stdio` | **把串口接到当前终端**——内核日志直接打在你眼前 |
| `-no-reboot` | 三重故障时不重启（裸机出错常表现为重启，调试时先摁住它） |

### 3.4 期待的画面

```
=== MOS booting ===
hello from kernel!
```

这两行出现在终端上的那一刻，意味着：**UEFI 加载了 Limine，Limine
按 ELF 头把内核摆进了高地址、建好页表、切到 64 位，跳进了 `_start`，
我们的汇编搭好了栈，`call kmain` 进入 Rust，串口初始化成功，字节
穿过模拟的 16550 芯片回到了你的屏幕。** 整条启动链第一次全通。

### 3.5 真机部署（阶段性验证用）

```fish
# 危险操作：sdX 必须是 U 盘，写错盘会毁掉那块盘的数据
lsblk                  # 先确认 U 盘设备名
sudo dd if=mos.iso of=/dev/sdX bs=4M status=progress oflag=direct
sync
```

然后目标机：插 U 盘 → 开机进启动菜单（通常按 F12）→ 选 U 盘。
注意两点（已写进根目录 README 的计划）：

- 需要在 UEFI 设置里**关闭 Secure Boot**（Limine 未做签名验证）
- 真机看串口日志需要 USB 转串口线；没有的话，等我们做好屏幕输出再上真机

## 4. 本章小结

- **为什么**：UEFI 只认 EFI 应用，内核必须由引导器代为加载
- **是什么**：Limine（双模式现代引导器）、ISO（目录的三重身份）、
  OVMF（模拟的 UEFI 固件）、BOOTX64.EFI（UEFI 写死的默认启动路径）
- **怎么做**：汇布局 → xorriso 打包 → bios-install → QEMU 挂 OVMF 开机；
  阶段性 `dd` 上真机

> **动手时的预埋知识点**：`limine` crate 提供引导协议的请求标记结构体，
> 我们会在内核里声明"我要帧缓冲"，用链接器保证它不被优化掉——这是
> 引导器和内核之间的"跨程序通信"，很妙的设计。
