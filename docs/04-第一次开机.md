# 04 · 第一次开机：Limine、ISO 与 QEMU

> 上一章：[03-串口输出](03-串口输出.md)。内核已经会说话了，
> 但话没人听见——因为它还躺在文件里，没人请它出场。
> 这一章接通最后一块拼图，迎来项目的"开机时刻"。

回头看看我们已经有什么：一个会编译的内核 ELF，一段会往串口写字节的代码。把它们拼起来按下开机键，应该就能看到 `hello from kernel!` 了——可是等等，第一章的故事里有个环节卡住了：**UEFI 物业根本不认识我们的内核**。物业只放行持 EFI 工牌的应用，裸机 ELF 连大门都进不去。

这一章就是去解决"进场资格"问题的。需要请三位新帮手，一位一位认识。

## 第一位：Limine——有工牌的中介

[Limine](https://github.com/limine-bootloader/limine) 引导器，社区维护的现代引导器，本身就是一个持证 EFI 应用。物业放它进场，它进场后替我们干完所有脏活：切 64 位长模式、建页表、探测内存（第 00 章那张表），然后把内核按 ELF 头摆进高地址，跳进去，退场。

选它还有一个决定性理由：**同一个镜像，BIOS 和 UEFI 机器都能启动**。也就是说老机器新机器通吃，真机兼容性直接拉满。

Limine 怎么知道要加载哪个内核？看配置文件 `limine.conf`——相当于它口袋里的"工作单"，上面写着启动项名字、用哪个协议、内核文件放在镜像的哪个路径。它和内核之间还有一套"交接班对话"叫**引导协议**：内核用请求标记声明"我要帧缓冲、我要内存映射"，Limine 看到标记就把数据备好递过来。这个精巧的跨程序通信，等下一章用帧缓冲时就能亲手摸到。

## 第二位：ISO——一只标准化的行李箱

内核和 Limine 现在是两个散装文件，得打包。打包格式用 ISO9660——光盘的文件系统格式，"行李箱"界的国际标准。

妙就妙在这只箱子有**三种身份**：它是磁盘上的一个普通文件；QEMU 把它当光盘插进虚拟光驱；`dd` 到 U 盘上，它就成了一张启动盘。一个目录，三种身份，全靠它是标准格式。

装箱的活由 `xorriso` 干，箱子里装这些：

```
iso_root/
├── limine.conf          # Limine 的工作单：启动项 + 内核路径
├── mos-kernel           # 我们的内核 ELF
├── limine-bios.sys      # Limine 的 BIOS 模式文件
├── limine-bios-cd.bin   # 同上（光盘引导记录用）
├── limine-uefi-cd.bin   # Limine 的 UEFI 模式文件
└── EFI/BOOT/BOOTX64.EFI # UEFI 固件默认寻找的启动文件（就是 Limine）
```

`EFI/BOOT/BOOTX64.EFI` 这个路径值得多看一眼：它是 UEFI 规范**写死**的默认启动路径。固件开机时挨个扫设备，找到这个路径就直接执行——好比所有商场的服务台都设在一楼正门左手边，谁都不用猜。你插 U 盘"插上就能进启动菜单"，背后就是这条规矩。

`limine.conf` 长这样（示意，具体语法以所用 Limine 版本为准，动手时核对）：

```
TIMEOUT=0

:MOS
    PROTOCOL=limine
    KERNEL_PATH=boot:///mos-kernel
```

工作单上写着：启动项叫 "MOS"，用 Limine 协议，把箱子根目录下的 mos-kernel 装载进来。

## 第三位：OVMF——给 QEMU 换上的 UEFI 戏服

QEMU 是个好演员，但它默认扮演的是一台 90 年代的老 BIOS 机器。我们的目标是 UEFI 真机，得给它换戏服：**OVMF** 就是那套 UEFI 戏服——UEFI 固件的开源实现。

戏服有两件：`OVMF_CODE.fd`（剧本，只读）和 `OVMF_VARS.4m.fd`（随身的笔记本，可写）。那本笔记本相当于真机主板 CMOS 电池供电的设置存储——你在蓝色界面里改的设置都记在那儿。

## 三步打包，然后按下开机键

构建流程（将由 Makefile 自动化）：

```
① cargo build                   # 编译内核 ELF（第 2 章的流程）
② 汇总 iso_root/ + xorriso 装箱成 mos.iso
③ limine bios-install mos.iso   # 往箱子里补写 BIOS 模式的引导记录
```

然后开机：

```fish
qemu-system-x86_64 \
    -M q35 -m 512M \
    -drive if=pflash,format=raw,readonly=on,file=/usr/share/ovmf/x64/OVMF_CODE.4m.fd \
    -drive if=pflash,format=raw,file=OVMF_VARS.4m.fd \
    -cdrom mos.iso \
    -serial stdio \
    -no-reboot -no-shutdown
```

参数逐个看：

| 参数 | 含义 |
|---|---|
| `-M q35` | 机器型号（较新的芯片组，更接近现代真机） |
| `-m 512M` | 内存 512 MB |
| `-drive if=pflash,...` | 给 QEMU 穿上 OVMF 戏服（CODE 只读 + VARS 可写） |
| `-cdrom mos.iso` | 把我们的"光盘"插进光驱 |
| `-serial stdio` | **把串口接到当前终端**——内核的话直接打在你眼前 |
| `-no-reboot` | 出错时不重启（裸机出错常表现为反复重启，调试时先摁住它） |

## 那一刻

```
=== MOS booting ===
hello from kernel!
```

这两行字出现时，请停一秒，因为这条链路上每一环都刚刚第一次贯通：物业（OVMF）放行了中介（Limine），中介按图纸把内核摆进高地址、搭好页表、切到 64 位，跳进 `_start`，我们的汇编立起了栈，`call kmain` 进入 Rust，串口旋钮拧到位，字条穿过模拟的 16550 芯片，落回你的终端。**接力赛跑完了全程。**

## 阶段性上真机

每个里程碑，把这只箱子放到真机上跑一次：

```fish
# 危险操作：sdX 必须是 U 盘。dd 没有撤销键，写错盘 = 那块盘的数据全没
lsblk                  # 先确认 U 盘设备名
sudo dd if=mos.iso of=/dev/sdX bs=4M status=progress oflag=direct
sync
```

然后目标机：插 U 盘 → 开机按 F12 进启动菜单 → 选 U 盘。两个注意事项：

- UEFI 设置里要**关闭 Secure Boot**（Limine 没做签名，物业见不到签名不放行）
- 真机想看串口日志需要一根 USB 转串口线；没有的话，等下一章做完屏幕输出再上真机也不迟
