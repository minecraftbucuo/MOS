# 08 · 内存管理（六）：内核堆 v2——让 free 真的 free

> 上一篇：[番外-真机时钟悬案](番外-真机时钟悬案.md)。番外结束，回到第八章
> 主线收尾。贪吃蛇你已经玩过了——它还顺带暴露了一个堆的隐患。bump 堆
> 跑通了 `Box`/`Vec`，但它的 free 是空操作——内存只出不进。本篇把堆
> 换成**能真正回收**的空闲链表分配器，顺带补上并发保护。

## 先看一个正在发生的 bug

番外篇的贪吃蛇，每次吃到苹果，蛇身 `Vec` 就要长一节。`Vec` 扩容的规矩是：申请一块
**更大的**新缓冲 → 把旧数据搬过去 → **向堆归还旧缓冲**。

前三步都正常，最后一步在 v1 堆这里发生了什么？看 `heap.rs`：

```rust
/// 归还。bump 版：什么都不做（下轮接 GlobalAlloc 时它必须在场）
pub fn dealloc(_ptr: *mut u8) {}
```

归还请求被扔进了虚空。游标只进不退，每吃一个苹果堆就永远胖一圈。
现在每局才漏几 KB，看不出事——但问题是结构性的：**内核里所有 `dealloc`
都是空操作**，任何长期运行的分配模式（反复开关的程序、第 9 章随时
创建销毁的进程）迟早把堆吃穿。到那天所有 `Box::new` 集体失败，而且
这类故障很难定位——出问题的代码逻辑全对，坏的是分配器本身。

所以这个问题必须在第 9 章之前解决。解法就是给堆换一个能真正回收的
实现：**空闲链表分配器（free-list allocator）**。

## 原理一：给每块内存戴一顶"帽子"

bump 堆不需要记账，因为它从不回收。要回收就得记账——而记账的第一课：
**归还回来的内存，你得知道它是谁**。

`dealloc` 收到的只是一个裸指针，指向归还内存的**开头**。块多大？
对齐多少？什么时候借的？一概不知。解法简单粗暴：**分配时在内存前面
偷偷多划 16 字节当"帽子"（header），把这块的大小写在帽子里**。

```
一块已分配的内存长这样：

  ┌──────────┬─────────────────────────┐
  │  帽子 16B │      载荷（给调用者的）      │
  │  size 记  │                          │
  │  本块总长  │                          │
  └──────────┴─────────────────────────┘
  ▲          ▲
  块头        返回给调用者的指针
```

`dealloc(ptr)` 一进来就把指针往回退 16 字节摸到帽子，读出大小——
谁借的、多大，全在帽子上。代价是**每块内存多背 16 字节**，这叫
元数据开销，所有真正的分配器都付这个钱。

配套的规矩：**块大小一律取 16 的倍数**（头部 16B + 载荷向上取整）。
这样只要堆起点对齐，每块的头都在 16 的倍数上，各块帽子的位置
可以直接用指针算术互推。

## 原理二：空闲链——把"货架"串起来

帽子解决了"这块是谁"，第二个问题：分配 8 字节时，**去哪里找一块
放得下的空闲内存**？

bump 时代答案是"游标后面永远是空的"。现在内存七零八落——有的在用，
有的刚还回来——需要一个地方登记所有空闲块。用一个**链表**：

```
free_head ──► [空闲 64B] ──► [空闲 1.5KB] ──► [空闲 96B] ──► 空
              （链上只挂空闲块；在用的块不在链上）
```

- **分配**：沿链扫描（首次适配 first-fit），找到第一块放得下的，
  从它前面切走需要的部分；剩下若还够自立门户（≥ 32B：一顶帽子 +
  最小载荷），就在原地戴上帽子继续留在链上
- **归还**：摸帽子知大小，把整块**按地址顺序**插回链上

"按地址顺序"是个关键的刻意设计，它的好处在合并时看得最清楚——

## 原理三：合并——防止内存碎成渣

只挂链不合并的话，空闲内存会碎成大量小块：空闲总量明明够，
却没有一块能放下较大的请求——这叫**外部碎片**。防碎的手段是
**合并（coalesce）**：归还时看看左右邻居，能拼就当场拼。

```
归还 96B 时发现：

  ... [prev 空闲 64B] [我 96B] [next 空闲 128B] ...

三块的地址首尾相接 → 拼成一块 288B
```

"按地址顺序插链"在这里兑现红利：归还时沿链扫到的 `prev` 和 `next`
恰好就是物理上的左右邻居，判断合并只需两句话——

- `prev 尾巴 == 我的头`？把我的大小加给 prev，我不单独入链
- `我的尾巴 == next 的头`？把 next 的大小并进来，链上跳过 next

一个直觉问题：**为什么不归还时立刻"整理内存"把碎片挤到一起？**
因为搬家要改所有指针，而堆根本不知道调用方把指针存哪了——所以
真正的分配器都不搬内存，只做相邻合并。碎片问题的彻底解决要靠
更聪明的算法（伙伴系统、slab），链表合并已够我们走很远。

## 原理四：并发保护——先补一个最小原语

v1 堆的注释里有一条默认约定：单核、且中断处理函数不碰堆。第 9 章
进程一来，这个约定必破：主代码分配到一半（链表正处在改了一半的
中间态），时钟中断插进来，处理函数也要分配——踩着半成品继续走，
链表当场损坏。

单核机器上有个极简且严格的解法：**临界区期间关中断**。中断是单核上
唯一能"插队"的执行流，把它关掉，临界区期间就不会有任何代码插进来。
这就是 `without_interrupts(f)`：进门拍张照（保存 RFLAGS，记住中断
原来开没开）、关中断、干完活、凭照片恢复原样。凭照片恢复而不是
无脑 `sti`，是为了支持嵌套——如果外层本来就关着中断，内层出来时
不该擅自打开。

> CAS 自旋锁是它的多核升级版，第 9 章统一 sync 时再请进来。

## 动手一：sync.rs 加 without_interrupts

`kernel/src/sync.rs` 追加：

```rust
use core::arch::asm;

/// 在"关中断临界区"里执行 f，结束后恢复进入前的中断状态。
/// 单核下这就是最可靠的锁：临界区里不可能有任何插队者。
pub fn without_interrupts<T>(f: impl FnOnce() -> T) -> T {
    let mut flags: u64;
    unsafe {
        // pushfq 把 RFLAGS 压栈，pop 进 flags —— 拍照
        asm!("pushfq", "pop {flags}", "cli",
             flags = out(reg) flags, options(nomem));
    }
    let r = f(); // 临界区：关着中断跑
    unsafe {
        // 凭照片恢复（若本来就没开中断，这里也不会误开）
        asm!("push {flags}", "popfq", flags = in(reg) flags, options(nomem));
    }
    r
}
```

两个 `options(nomem)` 告诉编译器这几条指令不碰内存（栈上的 push/pop
除外），别把周围的变量优化乱。

## 动手二：heap.rs 整体换心

结构不变（对外的 `init`/`alloc`/`dealloc`/`GlobalAlloc` 门面原样保留，
贪吃蛇等所有调用方零改动），内部实现整个替换。文件开头的状态和帽子：

```rust
//! 内核堆（第二版）：空闲链表分配器。对应教程：docs/08-6-内核堆v2.md
//!
//! 每块内存前有 16 字节帽子记账；空闲块串成按地址排序的链；
//! 分配首切首次适配，释放挂链并当场合并左右邻居。
//! 并发保护：所有操作包在 without_interrupts 里。

use crate::mm;
use crate::sync;
use core::sync::atomic::{AtomicUsize, Ordering};

const HDR: usize = 16;        // 帽子大小
const MIN_BLOCK: usize = 32;  // 最小块 = 帽子 + 16B 载荷

/// 帽子。已分配块：只有 size 有意义；空闲块：还挂在链上，next 生效
#[repr(C)]
struct Header {
    size: usize,       // 本块总字节数（含帽子），恒为 16 的倍数
    next: *mut Header, // 空闲链上的下一块
}

static START: AtomicUsize = AtomicUsize::new(0);
static SIZE: AtomicUsize = AtomicUsize::new(0);
static FREE_HEAD: AtomicUsize = AtomicUsize::new(0); // 链头，0 = 空链

fn round_up(x: usize, a: usize) -> usize {
    (x + a - 1) & !(a - 1)
}
```

`init` 变简单了——整个堆就是一块大空闲块：

```rust
pub fn init(pages: u64) -> bool {
    let first = match mm::alloc_frame_contig(pages) {
        Some(p) => p,
        None => return false,
    };
    let start = mm::phys_to_virt(first) as usize;
    let size = (pages * mm::PAGE_SIZE) as usize;
    START.store(start, Ordering::Relaxed);
    SIZE.store(size, Ordering::Relaxed);

    // 链上只有一块：整堆
    unsafe {
        (*(start as *mut Header)).size = size;
        (*(start as *mut Header)).next = core::ptr::null_mut();
    }
    FREE_HEAD.store(start, Ordering::Relaxed);
    true
}
```

分配——首次适配 + 切块：

```rust
pub fn alloc(len: usize, align: usize) -> Option<*mut u8> {
    let len = len.max(1);
    sync::without_interrupts(|| {
        let need = round_up(len, 16) + HDR; // 连帽子一起算的总需求

        let mut prev: *mut Header = core::ptr::null_mut();
        let mut cur = FREE_HEAD.load(Ordering::Relaxed) as *mut Header;
        while !cur.is_null() {
            let total = unsafe { (*cur).size };
            let payload = (cur as usize) + HDR;
            if total >= need && payload % align == 0 {
                // 放得下。剩余够自立门户（帽+最小载荷）就切块
                if total >= need + MIN_BLOCK {
                    let rest = (cur as usize + need) as *mut Header;
                    unsafe {
                        (*rest).size = total - need;
                        (*rest).next = (*cur).next; // rest 顶替 cur 的链位
                    }
                    if prev.is_null() {
                        FREE_HEAD.store(rest as usize, Ordering::Relaxed);
                    } else {
                        unsafe { (*prev).next = rest; }
                    }
                    unsafe { (*cur).size = need; } // 我的帽子记"实际占走"
                } else {
                    // 尾巴太小不切，整块拿走（帽子按原大小记）
                    if prev.is_null() {
                        unsafe { FREE_HEAD.store((*cur).next as usize, Ordering::Relaxed); }
                    } else {
                        unsafe { (*prev).next = (*cur).next; }
                    }
                }
                return Some(payload as *mut u8);
            }
            prev = cur;
            cur = unsafe { (*cur).next };
        }
        None // 扫完整条链：真没有了
    })
}
```

归还——挂链 + 双向合并：

```rust
pub fn dealloc(ptr: *mut u8) {
    if ptr.is_null() {
        return;
    }
    sync::without_interrupts(|| {
        // 摸帽子：这块多大
        let mut block = (ptr as usize - HDR) as *mut Header;
        let size = unsafe { (*block).size };

        // 按地址顺序找插入点（prev/next 恰好就是物理左右邻居）
        let mut prev: *mut Header = core::ptr::null_mut();
        let mut cur = FREE_HEAD.load(Ordering::Relaxed) as *mut Header;
        while !cur.is_null() && (cur as usize) < (block as usize) {
            prev = cur;
            cur = unsafe { (*cur).next };
        }

        unsafe {
            // 先挂上链
            if prev.is_null() {
                FREE_HEAD.store(block as usize, Ordering::Relaxed);
            } else {
                (*prev).next = block;
            }
            (*block).next = cur;

            // 合并前邻：prev 的尾巴正好接上我的头
            if !prev.is_null() && (prev as usize) + (*prev).size == block as usize {
                (*prev).size += size;
                (*prev).next = (*block).next;
                block = prev; // "我"变成了合并后的 prev
            }
            // 合并后邻：我的尾巴正好接上 cur 的头
            if (block as usize) + (*block).size == cur as usize {
                (*block).size += (*cur).size;
                (*block).next = (*cur).next;
            }
        }
    })
}
```

最后加一个体检函数，验证时要靠它：

```rust
/// (空闲总量, 空闲块数)。分配/归还应当守恒——验证全靠它
pub fn stats() -> (usize, usize) {
    let mut total = 0;
    let mut count = 0;
    let mut cur = FREE_HEAD.load(Ordering::Relaxed) as *mut Header;
    while !cur.is_null() {
        total += unsafe { (*cur).size - HDR }; // 帽子不算空闲量
        count += 1;
        cur = unsafe { (*cur).next };
    }
    (total, count)
}
```

## 验证：分配要"守恒"

`kmain` 里、`game::init()` 之前加一段自检：

```rust
// 堆自检：反复借还各种尺寸，空闲量必须分毫不差地回来
let (free0, _) = heap::stats();
let mut ptrs: alloc::vec::Vec<*mut u8> = alloc::vec::Vec::new();
for i in 0..1000 {
    let n = 8 + (i * 37) % 512; // 各种奇怪尺寸
    ptrs.push(heap::alloc(n, 16).expect("heap selftest: alloc failed"));
}
for p in &ptrs {
    heap::dealloc(*p);
}
let (free1, blocks) = heap::stats();
console::print(&alloc::format!(
    "heap selftest: {} blocks, free {} -> {} {}\n",
    blocks, free0, free1,
    if free1 == free0 { "PASS" } else { "FAIL!" }
));
```

期待输出 `PASS`。`free1 == free0` 这一条守恒律能同时抓住三类错：
归还丢失（总量变少）、没切干净（块数异常）、合并做错（块数/总量异常）。

真正的实战验收：**贪吃蛇随便玩多少局、长多长，都不会再有分配失败**——
`Vec` 每次扩容归还的旧缓冲，这次真的回到了空闲链上。

## 本章小结

- bump 堆的 free 是空操作：所有归还都打水漂，长期运行必然堆满——
  必须在第 9 章进程创建销毁之前解决
- 帽子（header）让 `dealloc` 凭一块裸指针认出"这是谁、多大"
- 空闲链按**地址顺序**维护，合并只需检查左右邻居首尾相接
- 合并不能"搬家整理"（不知道调用方的指针藏在哪），只能就地相邻合并
- 单核的并发保护 = `without_interrupts`：拍照（存 RFLAGS）→ cli →
  干活 → 凭照片恢复
- 验证分配器靠守恒律：借多少、还多少，空闲总量必须分毫不差

**里程碑**：堆自检 PASS，`free` 第一次真正回收内存 ✅
