# 00 · 启动流程：从按下电源到你的代码运行

> 自制 OS 的第一个心理障碍是：**操作系统还没写出来之前，谁来运行你的程序？**
> 这一章讲清楚整条启动链，后面的每一步代码都能对号入座。

## 1. 启动链条总览

```
按下电源
   │
   ▼
CPU 复位，从固定地址开始执行 ──► 这是主板上的固件（UEFI，就是那个蓝色设置界面）
   │
   ▼
UEFI 初始化硬件、扫描启动设备（硬盘/U 盘）
   │
   ▼
读取 U 盘 EFI 分区里的引导程序 ──► 我们用现成的【Limine 引导器】
   │
   ▼
Limine 做三件事：
   1. 打开显示（帧缓冲）           ◄─ 我们不用自己写显示初始化
   2. 检测物理内存分布             ◄─ 我们不用自己写内存探测
   3. 把 CPU 切到 64 位长模式      ◄─ 我们不用自己写模式切换汇编
   然后跳转到【我们内核的第一条指令】
   │
   ▼
★ 从这里开始，全是你的代码 ★
```

### 各环节是什么

**UEFI 固件**：焊在主板上的小程序（存在闪存芯片里），就是开机时按 F2/Del 进的那个设置界面的本体。它负责最基本的硬件初始化，然后按 UEFI 标准从启动设备上找引导程序。它不是操作系统——它只负责"把火炬递出去"。

**Limine 引导器**：一个第三方引导程序（[github.com/limine-bootloader/limine](https://github.com/limine-bootloader/limine)）。它被 UEFI 加载后，替我们干完所有"脏活"：

| 它做的事 | 如果自己做要付出什么 |
|---|---|
| 切换到 64 位长模式 | 几百行汇编：实模式 → 保护模式 → 长模式，两套页表搭建，是老教程劝退第一大坑 |
| 打开显示、建立帧缓冲 | 和 VESA/UEFI GOP 打交道 |
| 探测物理内存布局 | 解析 BIOS/UEFI 的内存映射接口 |
| 把内核 ELF 加载到内存并跳转 | 解析 ELF 文件格式、处理重定位 |

**我们的内核**：Limine 工作完成后，CPU 处于一个干净的 64 位环境，有现成的页表和一块可写的帧缓冲，然后执行权交给内核的第一条指令。之后 UEFI 和 Limine 都不再运行——内存里只剩我们的代码。

## 2. 三个关键认知

### 认知 1：Limine 让我们跳过最劝退的部分

老教程（比如"30 天自制操作系统"、OSDev wiki 的裸机路线）从实模式 16 位汇编写起，几百行汇编之后才能打出第一个字符。用现代引导器，我们第一行代码就是纯净的 64 位环境，精力可以花在操作系统本体——中断、内存、进程——上。

这是取舍：自己写引导能学到更多"历史考古"知识，但那些知识对写现代 OS 帮助有限。学习性价比上，现代路线完胜。

### 认知 2：内核本质上是一个"特殊的程序"

它和普通 Rust 程序的区别只有两点：

1. **不能用标准库**。`std` 里的文件、网络、线程全都依赖操作系统——而我们是来**写**操作系统的，没有人给我们托底。内核是 `no_std` 的，只能用核心库 `core`（纯计算部分：整数、字符串切片、`Option`/`Result` 等）和 `alloc`（前提是我们自己实现了堆分配器——第 2 阶段的事）。
2. **入口不是 `main`**。普通程序的入口由 C 运行时（crt0）和操作系统决定；内核的入口符号由我们自己的**链接脚本**指定，一般是 `_start`。

其余的一切——`struct`、`match`、所有权、泛型——全部照常可用。写内核的 Rust 和写应用的 Rust 是同一种语言。

### 认知 3：我们的输出手段是帧缓冲（framebuffer）

没有 `println!`，没有 `write(1, buf, n)`，这些"理所当然"的东西背后都是操作系统的代码。内核阶段 0 的输出通道是 **Limine 递给我们的帧缓冲**：一块裸的内存区域，每个像素占 4 字节，往里写数值就是在屏幕上画颜色。串口（COM1）是第二条通道——QEMU 里敲一行命令就能看到内核日志，真机调试时也靠它，后面会加上。

## 3. 开发环境：每个工具是干嘛的

| 工具 | 作用 | 为什么需要 |
|---|---|---|
| `rustup` + `rustc` + `cargo` | Rust 工具链 | 写内核本体。额外要装裸机编译组件（后面章节用到时再装） |
| `qemu-full` | 硬件模拟器 | 模拟一台 x86 电脑运行内核。开发全程用它，比每次刻 U 盘重启真机快一万倍 |
| `ovmf` | UEFI 固件的模拟实现 | QEMU 默认模拟老式 BIOS；装上 OVMF 才能模拟 UEFI 启动，和真机行为一致 |
| `xorriso` | 制作 ISO 镜像 | 把内核 + Limine 打包成可启动 `mos.iso`，QEMU 和真机 U 盘都用它 |
| `wget` | 下载工具 | 下载 Limine 二进制 |

安装（Arch Linux）：

```bash
sudo pacman -S --needed qemu-full ovmf xorriso wget
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y   # rustup，官方安装器
```

## 4. 开发循环

```
改代码 ──► make iso（打包）──► make run（QEMU 启动看效果）
   ▲                                  │
   └────────── 看日志/调试 ◄───────────┘
```

阶段性（每个里程碑）才刻 U 盘上真机：

```bash
make burn DEV=/dev/sdX   # dd 到 U 盘，注意 sdX 别写错成硬盘！
```

真机注意：需要在 UEFI 设置里**关闭 Secure Boot**（Limine 默认不签名）。
