# 00 · 启动流程：从按下电源到你的代码运行

> 自制 OS 的第一个心理障碍是：**操作系统还没写出来之前，谁来运行你的程序？**
> 这一章把整条启动链一步步讲清。搞懂它，之后每写一段代码，
> 你都知道它跑在链条的哪一棒上。

## 故事从按下电源开始

你按下电源键的那一瞬间，CPU 其实什么都不知道：不知道硬盘里有什么，更不知道你的内核在哪。它只会做一件出厂时就固定的事——**从一块固定地址的芯片里开始执行指令**。

那块芯片焊在主板上，里面是 **UEFI 固件**。这个名字听着陌生，但你一定见过它：开机时按 F2 进的那个蓝色设置界面，就是它。UEFI 上电后做两件事：初始化基本硬件，然后按 UEFI 规范逐个扫描启动设备（硬盘、U 盘），寻找可加载的 EFI 应用程序。

UEFI 只能加载一种格式：**EFI 应用程序**。我们的内核是裸机 ELF 文件，不符合这个格式，UEFI 不会加载它。

解决办法：用引导器作为中间加载者——它本身是一个 EFI 应用，有被 UEFI 加载的资格；加载后由它把我们的内核装进内存。这个引导器就是 **Limine**。它加载后，替我们完成内核启动所需的全部底层初始化：

| 它做的事 | 如果自己干要付出什么 |
|---|---|
| 切换到 64 位长模式 | 几百行汇编：实模式 → 保护模式 → 长模式，两套页表搭建，是老教程劝退第一大坑 |
| 打开显示、建立帧缓冲 | 和 VESA/UEFI 显示接口打交道 |
| 探测物理内存布局 | 解析固件的内存映射接口 |
| 把内核 ELF 加载到内存并跳转 | 解析 ELF 文件格式、处理重定位 |

干完之后，Limine 把执行权转移到内核的第一条指令，之后自己不再运行。**从此内存里只剩我们的代码。**

整个启动过程如下：

```
按下电源
   │
   ▼
CPU 复位，从固定地址开始执行 ──► 主板上的 UEFI 固件
   │
   ▼
UEFI 初始化硬件、扫描启动设备（硬盘/U 盘）
   │
   ▼
UEFI 加载启动设备上的【Limine 引导器】（EFI 应用）
   │
   ▼
Limine：开显示、探内存、切 64 位 ──► 跳转到【内核的第一条指令】
   │
   ▼
★ 从这里开始，全是你的代码 ★
```

如果没有 Limine，我们就得从 16 位实模式汇编写起，几百行之后才能打出第一个字符——很多"30 天自制操作系统"教程就是这么劝退读者的。那些内容偏历史遗留细节，对写现代操作系统帮助有限；把精力省下来花在中断、内存、进程上，性价比高得多。这是我们用现成引导器的理由，一个坦然的取舍。

## 内核其实是一个"特殊的程序"

写内核之前，还得掰清楚一件事：它和我们平时写的 Rust 程序，到底差在哪？

普通程序的每一步都建立在操作系统提供的服务之上：文件、网络、线程、内存分配，全由操作系统代管。而内核**自己就是操作系统**：没有标准库替你管这些（那些本来就是操作系统才有的东西），一切要自己实现。

具体来说，差别只有两处：

1. **不能用标准库**。`std` 里的每一件东西都依赖操作系统提供的服务，而我们就是来写操作系统的，没有谁给我们提供这些服务。内核是 `no_std` 的，只能用 `core`——纯计算的部分（整数、切片、`Option`/`Result` 这些不碰硬件的部分）。
2. **入口不是 `main`**。普通程序从哪儿开始执行，是别人（C 运行时和操作系统）说了算；内核从哪儿开始，由我们自己的**链接脚本**指定。

除此之外——`struct`、`match`、所有权、泛型——全部照常。写内核的 Rust 和写应用的 Rust 是同一种语言，只是运行环境里没有操作系统。

## 我们的输出通道：帧缓冲和串口

不能被 UEFI 加载只是第一个困难，还有第二个：内核没有任何输出手段。没有 `println!`，没有 `write()`——这些"理所当然"的输出手段，背后全是操作系统的代码，而我们正在从零写它。

内核阶段有两种最基础的输出方式：

- **帧缓冲（framebuffer）**：Limine 把显存区域的信息交给内核——一大块内存，每个像素 4 个字节，往里写数值，屏幕上对应的点就变颜色。以后我们用它画字符、做屏幕输出。
- **串口**：一根按位发送数据的线。QEMU 里一条命令就能把串口输出接到你的终端；真机出问题时，串口日志往往能告诉你死在哪一步。

## 开发环境：需要安装的工具

启动的故事到这里讲完了。开工之前，先认识一下本章要安装的工具——后面每一章都会跟它们打交道：

| 工具 | 是什么 | 为什么需要 |
|---|---|---|
| `rustup` + `rustc` + `cargo` | Rust 工具链 | 写内核本体 |
| `qemu-full` | 硬件模拟器 | 模拟一台 x86 电脑。开发全程用它，比每次刻 U 盘重启真机快一万倍 |
| `ovmf` | UEFI 固件的模拟实现 | QEMU 默认模拟的是老式 BIOS；装上 OVMF 才能模拟 UEFI，和真机行为一致 |
| `xorriso` | 制作 ISO 镜像的工具 | 把内核和引导器打包成可启动的 `mos.iso`，QEMU 和真机 U 盘都用它 |
| `wget` | 下载工具 | 下载 Limine 二进制 |

安装（Arch Linux）：

```bash
sudo pacman -S --needed qemu-full ovmf xorriso wget
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y   # rustup，官方安装器
```

## 开发循环

```
改代码 ──► make iso（打包）──► make run（QEMU 启动看效果）
   ▲                                  │
   └────────── 看日志/调试 ◄───────────┘
```

阶段性（每个里程碑）才刻 U 盘上真机：

```bash
make burn DEV=/dev/sdX   # dd 到 U 盘。sdX 千万别写错——dd 不可恢复，写错盘会毁掉那块盘的数据
```

真机注意：需要在 UEFI 设置里**关闭 Secure Boot**（Limine 默认不做签名验证，固件验签不通过就不会加载它）。
